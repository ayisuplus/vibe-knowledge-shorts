## 0. 选题定位与风险提示

**一句话：** 树是"把一个大问题一层层分叉拆小"的结构。自然界用它输送水和养分，计算机用它找东西、读懂语言，AI 用它做决定。

**主线问题：** 为什么自然界、计算机、AI 都爱用树？
**结尾落点（能用上的）：** 遇到复杂的事，就画一棵树：一层只问一个问题，一层层往下分。

**为什么适合这个账号：**
- 每个人每天都在用树，只是没意识到：电脑文件夹、家谱、公司架构、手机里的通讯录排序、网购搜索
- 天生适合 3D：生长、分叉、旋转、剪枝、一棵变成一片森林，都是看得见的动作
- "倒着长"是一个好奇心钩子，而且片子里有一个漂亮的视觉答案（根系）

**风险：**

1. **容易变成数据结构百科。** 每种树都要回答同一个问题："它把什么大问题，拆成了什么小问题？"讲不出这一点的树就不放。
2. **术语门槛。** 屏幕上不出现"时间复杂度""O(log n)"。用"最多猜 7 次""最多走 40 步"这种能数的数字代替。
3. **3D 渲染性能。** HyperFrames 的 Three.js 渲染跑在无头 Chrome 里，森林、4K、阴影都会拖慢。进入制作前先做一个 5 秒技术样片，测清楚每帧耗时。
4. **简化的分寸。** 红黑树只讲"为什么要旋转"，不讲五条性质；B+ 树容量是估算；决策树的分裂标准（信息增益）只用"哪个问题最能把西瓜分开"来说。上屏统一用"大约""最简单的情况"。
5. **AI 生成内容标识。** 如果写实的大树或生命之树用 Codex 生成图，发布时要主动勾选 AI 生成声明（同第五期）。

## 2. 核心内容（按片中出场顺序）

### 2.1 种子与生长：一条规则长出一棵树

- 1968 年，理论生物学家**林登迈耶**（Aristid Lindenmayer）提出 L-system，用来描述藻类等植物的生长：几条"把这一段替换成那几段"的规则，反复执行，就得到分叉结构。**学术**
- 上屏：一条规则（"一根枝 → 一根枝 + 两根小枝"）执行 1 次、2 次……6 次，一棵树长出来。这就是**递归**：用自己定义自己。
- 自然界的分叉：河流水系、闪电、血管、肺。人的支气管从气管开始，大约**分叉 23 代**到达肺泡（Weibel 模型）。**教材**
- 制作提示：主树本身就用程序化算法生成（空间殖民算法或 L-system），**"一条规则长出一棵树"在画面上是真的**，不是示意。

### 2.2 根系：为什么程序员的树是倒着长的

- 真实的根系主要横向铺开：侧根通常能伸到树冠边缘（滴水线）之外 **2–3 倍**的距离，大部分根集中在**表层约 30 厘米**的土里。**推广**（佛罗里达大学推广站；一篇综述给出的平均最大根展是 2.9 倍滴水线，因树种在 1.7–3.8 倍之间）
- 计算机里的树把**根画在最上面**，往下分叉。画面答案：镜头钻到地下，根就是一棵倒着长的树。
- **为什么这么画：没有权威出处。** 常见解释是"从上往下读、根是入口"。片中不说原因，只用画面给出对应关系（见第 5 节）。
- "树"这个数学术语：英国数学家**凯莱**（Arthur Cayley）**1857 年**的论文《论被称为树的解析形式》，他研究的树就是有根的。**学术**

### 2.3 什么才算树

- 定义：一个根；除了根，每个节点恰好有一个父节点；没有环。n 个节点的树恰好有 n−1 条边。**教材**
- 生活中的树：电脑文件夹（"C 盘 → 用户 → 文档 → ……"）、家谱、公司组织架构、网页结构（DOM）。
- 反例（一句带过，帮助理解）：朋友关系不是树。A 认识 B、B 认识 C、C 又认识 A，形成了环。

### 2.4 二叉搜索树：猜数字

- 规则：左边都比我小，右边都比我大。
- 猜 1–100 的数，每次猜中间，**最多 7 次**一定猜中（2⁷ = 128 ≥ 100）。**自算**
- **退化**：如果按 1、2、3……的顺序依次放进去，每个数都比前一个大，全挂在右边，树变成一根竹竿，找一个数可能要走 100 步。**教材**
- 画面：数字像果子一样落进根系，各归其位；顺序插入时根系长成一根直线，然后**倒下**。

### 2.5 红黑树：把歪了的树扶正

- 平衡树的思路：插入后如果一边太重，就做一次**旋转**，把树扶正。
- 第一种自平衡二叉搜索树是 **AVL 树（1962）**。**教材**
- 红黑树：前身是 Bayer 1972 年的"对称二叉 B 树"；**1978 年 Guibas 和 Sedgewick** 给节点涂上红、黑两色，起了现在的名字。**学术 / 百科**
- **名字的由来有两个版本**，都出自作者本人的回忆：一说施乐 PARC 的彩色激光打印机印红色最好看；一说当时手边只有红笔和黑笔。**百科**（片中如果用，要写"一种说法是……"，或者两个都说）
- 保证：n 个节点的红黑树，高度不超过 2·log₂(n+1)。**教材**（CLRS 引理 13.1）
  - 100 万个数：最多约 **40 层**（2·log₂(1,000,001) ≈ 39.9）。对比：退化成竹竿要 100 万层。**自算**
- 它在哪：C++ 的 std::map（主流实现）、Java 的 TreeMap、Java 8 起 HashMap 一个桶里挤了 8 个以上元素时会改成红黑树、Linux 内核。**百科**
- **讲多深：建议只讲"歪了 → 转一下 → 正了"，不讲五条性质。** 红、黑两色只当视觉标签。

### 2.6 B+ 树：为什么上亿条数据也能秒查

- B 树：**Bayer 和 McCreight**，在波音研究实验室提出（1970 年报告，1972 年发表）。字母 B 代表什么，作者没有明确说过。**学术 / 百科**
- B+ 树：每个节点放很多岔路，树就又矮又宽。数据库最怕读硬盘，树越矮，读硬盘的次数越少。
- MySQL 的 InnoDB 存储引擎一页 16KB。按常见假设（主键 8 字节、指针 6 字节、每行约 1KB），三层 B+ 树大约能存 **1170 × 1170 × 16 ≈ 2190 万行**。**估算**（实际受行宽、页填充率影响，通常更少。上屏写"三层，大约就能装下两千万条"）
- 画面：根系的某一段变成又矮又宽的"书架"，镜头从书架间飞过，三步就找到一本书。

### 2.7 语法树：一句话为什么能读出两个意思

- 「**咬死了猎人的狗**」：
  - 切法 1：[咬死了] [猎人的狗]（猎人的狗被咬死了）
  - 切法 2：[咬死了猎人的] [狗]（是那条狗咬死了猎人）
  - 词的顺序一样，**树不一样，意思就不一样**。这属于结构层次歧义。**教材**（分析为本档案推导，与语法学通行分类一致）
- 计算器 / 程序：「1 + 2 × 3」，× 在树的更深一层，先算，结果是 7 而不是 9。**教材**
- 画面：词语排在土层的截面上，下方同时长出两棵根，各对应一个意思。

### 2.8 决策树：挑西瓜

- 周志华《机器学习》（2016，"西瓜书"）第 4 章用**西瓜数据集**讲决策树：色泽、根蒂、敲声、纹理、脐部、触感。**教材**
- 每一层选一个"最能把好瓜和坏瓜分开"的问题（信息增益，**简化**为这句话）。
- 起源：CART（Breiman 等，1984），ID3（Quinlan，1986）。**学术**
- "20 个问题"游戏：每个问题只答是或否，20 个问题最多能区分 2²⁰ = **1,048,576** 种东西。**自算**
- 画面：一个西瓜沿着树枝往上（地上部分）一路被分流，最后落到"好瓜 / 坏瓜"的叶子上。

### 2.9 剪枝：问得太细，反而会看错

- 树长得太细，会把训练数据里的偶然特征（比如"这一个瓜恰好是周二买的"）当成规律，这叫**过拟合**。**教材**
- **剪枝**：把这些只对个别例子有用的分叉剪掉。西瓜书 4.3 节分为预剪枝和后剪枝。**教材**
- 画面：一把剪刀剪掉过密的细枝。和真实园艺修剪是同一个动作，呼应开头的真树。

### 2.10 随机森林：一棵树会看走眼，那就种一片

- **Breiman 2001**。每棵树只看一部分数据、一部分特征，最后投票。**学术**（"随机决策森林"的想法更早，Tin Kam Ho 1995）
- 画面：镜头拉远，主树旁边长出一片小树，每棵树头顶亮起"好瓜 / 坏瓜"的票，多数胜出。

### 2.11 梯度提升树（可选）：下一棵专门改上一棵的错

- Friedman 2001 提出梯度提升；XGBoost（陈天奇等，2016）把它做成了表格数据竞赛里最常用的工具之一。**学术**
- 在表格数据（如金融风控、推荐排序的部分环节）上，树模型至今仍很常用。**简化**（不要说"比深度学习强"）
- 片中可以只用 3 秒：第二棵树长在第一棵的"错题"上。如果时长紧张就删掉。

### 2.12 搜索树：AlphaGo 怎么想下一步

- 蒙特卡洛树搜索（MCTS，名字来自 Coulom 2006）：把"我走这里 → 对手走那里 → ……"展开成一棵树，往看起来有希望的方向多试几次。**学术**
- AlphaGo 用的是神经网络加蒙特卡洛树搜索（Silver 等，Nature 2016 年 1 月）。2016 年 3 月以 **4 : 1** 战胜李世石。**学术 / 百科**
- 围棋合法局面约 **2.08 × 10¹⁷⁰** 种（Tromp 2016），不可能全部展开，所以只在有希望的枝上深挖。**学术**
- 画面：树顶伸出一根发光的枝，前端不断分叉向未来延伸，亮的枝越来越亮，暗的枝停止生长。

### 2.13 生命之树：回到起点

- **1837 年**，达尔文在笔记本 B 第 36 页画了一棵分叉的小树，旁边写着「**I think**」。**学术 / 百科**（剑桥大学图书馆藏）
- 1859 年《物种起源》**唯一的一幅插图**，就是一张分叉的树状图。**学术**
- 画面：镜头一路拉远，主树成为一片森林中的一棵，再拉远，森林成为生命之树上的一根枝。最后定格在一棵树的剪影旁手写的「I think」（用达尔文原句时不要仿造他的手迹，用字体呈现）。

## 4. 故事素材（按上屏价值排序）

1. **「咬死了猎人的狗」**：中文观众一看就懂，两棵树并排，是本期最"原来如此"的一刻。
2. **猜 1–100 最多 7 次**：观众可以自己在心里试，互动感强。
3. **竹竿倒下**：退化的二叉树变成一根直线然后倒下，好笑又好懂。
4. **剪刀剪枝**：机器学习术语和园艺动作是同一个词、同一个动作，最适合用 3D 呈现。
5. **达尔文的「I think」**：结尾的情绪落点，安静、有余味。
6. **红黑树名字的两个说法**（激光打印机 / 手边的笔）：可以做成一行小字彩蛋，不是必需。
7. **20 个问题能猜中 100 万种东西**：放在决策树段开头当钩子。

## 5. 不要用的流传说法

| 说法 | 问题 | 处理 |
|---|---|---|
| "高德纳（Knuth）说过计算机科学家把树倒着画是因为……" | 搜不到可靠原文 | 不引用。片中不解释为什么倒着画，只用根系画面回答 |
| "B 树的 B 代表 Bayer / Boeing / Balanced" | 作者没有明确说过 | 不提 |
| "单表超过 2000 万行必须分表" | 经验值，依赖行宽等假设 | 只说"三层大约能装两千万条"，不给建议 |

| "达尔文画的就是《物种起源》里那张图" | 不是同一张。1837 年的是笔记草图，1859 年的是书中插图 | 分开说 |

## 6. 反方与复杂性（脚本至少用一条，保持中立）

- **不是所有东西都适合用树。** 朋友关系、地图路线有环，要用"图"。树的力量来自"每个节点只有一个上级"，代价也在这里（一份文件不能同时放在两个文件夹里，所以才有"快捷方式"）。
- **画树也会画错。** 决策树问得越细越容易过拟合，所以才要剪枝、才要森林。这一条可以自然地变成结尾提醒："画树时，别问太细。"

## 8. 视觉方向（提案，等样张确认）

**基调：明亮桌面模型风**，沿用上期定下的"明亮、真实、平静"。不走暗黑赛博霓虹。

- **空间**：米白摄影棚，柔和天光，主树立在一块**剖开的土层切片**上（像博物馆的地层模型），地上地下同时可见。这是全片的"舞台"。
- **材质**：树干木质，叶子用低多边形加柔和次表面散射；数据结构的节点是哑光陶土小球；根系从泥褐色逐渐过渡到发光的暖金色线条（表示"变成了计算机的树"）。
- **配色（不用紫）**：

| 用途 | 颜色 |
|---|---|
| 背景纸色 | #F4EFE6 |
| 土层 | #8B6A4F / #6B4E3A |
| 木 | #8A5A3B |
| 叶 | #5E9E5A / #8CC084 |
| 发光节点 / 被点亮的枝 | 暖金 #F2C14E |
| 强调 | 珊瑚 #E8705A / 暖橙 #F08A3C |
| 红黑树 | 红 #D9483B / 墨 #23262B |
| 文字 | 墨灰 #23262B |

- **运镜**：慢推、环绕、穿越地表；基本不抖；转场全部是"镜头飞到下一根枝或根"，不用硬切。
- **文字**：只放画面需要的词和数字；数字用等宽字体；字幕区（画面底部）保持空，字幕单独出 SRT。
- **封面**：4:3 和 3:4。主图用剖面巨树：上半枝叶，下半金色根系。

**技术路线：**
- HyperFrames + Three.js 适配器。主树用固定随机种子的空间殖民算法生成，每根枝的生长量是时间的纯函数 g(t)，可任意拖动、可复现。
- 森林用 InstancedMesh；阴影只开主光；后期辉光（bloom）先测性能再决定。
- 写实元素（达尔文笔记、真实树皮纹理）用 Codex 生成或做贴图，发布时声明 AI 生成。
- **第一步先做技术样片**：种子长成小树 + 镜头穿过地表，5 秒，测 1080p 和 4K 的每帧耗时。

## 9. 进入第二阶段前，需要你拍板的问题

1. **时长**：第四、五期是 160 秒（跟固定 BGM 一样长），第六期是 265 秒。这期内容多，我建议 **约 4 分钟**。如果要压到 160 秒，就砍掉 B+ 树、梯度提升树和搜索树。
2. **音乐**：
   - A. 继续用第一期的固定 BGM（160 秒，时长会被它限制）
   - B. 像第六期一样用 AI 现做：一首"从一颗种子慢慢长大"的曲子，开头安静、逐层加乐器、到森林和生命之树时最满。**我推荐 B**，生长的节奏可以和音乐的层层叠加对上。
3. **画风**："明亮桌面模型风 + 土层剖面"可以吗？还是你说的"酷炫"更偏暗色科技感？
4. **红黑树讲多深**：建议只讲"歪了 → 转一下 → 正了"，不讲规则。
5. **可选内容**：梯度提升树、红黑树名字的小彩蛋，要不要？
6. **标题候选**：
   - 「程序员的树，为什么是倒着长的？」（好奇心型，和开场钩子一致）
   - 「一棵树，长出了整个计算机世界」
   - 「从一颗种子，到 AlphaGo」
